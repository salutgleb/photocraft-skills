# PhotoCraft: общие правила

PhotoCraft это бесплатный открытый редактор, устроенный как Фотошоп: те же меню, слои, маски, PSD. Каждый пункт меню в нём это команда с именем вроде `image.canvasSize`. Утилита `photocraft-cli` запускает те же команды без окна программы. Через неё ты и работаешь.

Встроенной нейросети в PhotoCraft нет. Генеративной заливки и дорисовки тоже нет. Всё, что ты делаешь, это обычные операции редактора: выделение, маска, свет, цвет, размер, сохранение.

Список команд в этих скиллах сверен с PhotoCraft 0.23.1. Программа в ранней альфе и быстро меняется, поэтому действуют два правила: сверяй команды с установленной версией (раздел 2) и всегда начинай с пробы на одном файле (раздел 5).

## 1. Найди photocraft-cli

Проверь по порядку, пока не сработает:

| Система | Где лежит |
|---|---|
| Windows, обычная установка | `%LOCALAPPDATA%\Programs\ArtCraft\PhotoCraft\photocraft-cli.exe` |
| Windows, установка для всех | `C:\Program Files\ArtCraft\PhotoCraft\photocraft-cli.exe` |
| Windows, переносная версия | рядом с `photocraft.exe` |
| macOS | отдельный архив `photocraft-cli-<версия>-macos-universal.zip`, в саму программу утилита не входит |
| Linux, пакеты deb и rpm | `/usr/bin/photocraft-cli` |
| Linux, AppImage | тот же файл с ключом `--cli`, например `./photocraft-…AppImage --cli --help` |

На Windows утилита не добавлена в PATH, вызывай её по полному пути в кавычках.

На macOS, если утилиты нет:

1. Скажи человеку, что нужен архив `photocraft-cli-<версия>-macos-universal.zip` со страницы https://github.com/storytold/photocraft/releases/latest (около 120 МБ, после распаковки 230 МБ).
2. Распакуй: `ditto -x -k photocraft-cli-<версия>-macos-universal.zip ~/photocraft-cli`
3. Проверь подпись Apple: `spctl --assess --type install -vv ~/photocraft-cli/photocraft-cli-<версия>-macos-universal/photocraft-cli`. Должно быть `accepted` и `Notarized Developer ID`.
4. Дальше вызывай по полному пути.

Сам скачивать и ставить программы без согласия человека не начинай: сначала скажи, что нужно и сколько места займёт.

Проверка, что всё работает:

```sh
photocraft-cli --version
```

Запомни путь к утилите на время работы. Ниже она везде названа `photocraft-cli`.

## 2. Сверь команды с установленной версией

Главный источник правды это сама утилита, а не этот файл:

```sh
photocraft-cli commands --filter removeBackground
photocraft-cli commands --filter canvasSize
photocraft-cli commands --json --filter image.
photocraft-cli batch --help
```

`commands` печатает имя команды и её параметры. Перед первым запуском в сессии проверь так каждую команду, которую собираешься вызвать. Если параметры в выводе отличаются от написанного в скилле, верь выводу и скажи человеку, что именно изменилось.

Краткий справочник команд с параметрами лежит в `references/commands.md`.

## 3. Четыре способа запуска

**Узнать размер и состав файла.** Ничего не меняет:

```sh
photocraft-cli info фото.jpg --compact
```

**Перевести в другой формат:**

```sh
photocraft-cli convert вход.psd выход.jpg --quality 90
```

**Выполнить команды над одним файлом:**

```sh
photocraft-cli run вход.jpg \
  --cmd image.autoContrast \
  --cmd filter.sharpen.unsharpMask --params '{"amount":60,"radius":1,"threshold":2}' \
  --out выход.jpg --quality 90 --metadata none
```

`--params` относится к той `--cmd`, которая стоит прямо перед ним. Команды идут по порядку. Без `--out` файл не сохраняется, а результаты команд печатаются: так удобно что-то измерить, ничего не записывая.

**Обработать папку одним набором шагов:**

```sh
photocraft-cli batch --actions шаги.json \
  --in ./исходники --out ./готово \
  --format jpg --quality 90 --metadata none \
  --error-log ./готово/_ошибки.txt
```

Файл шагов это список пар «команда, параметры»:

```json
[
  ["image.autoContrast", {}],
  ["filter.sharpen.unsharpMask", {"amount": 60, "radius": 1, "threshold": 2}]
]
```

Полезные ключи `batch`:

- `--recursive` берёт и вложенные папки, но результаты кладёт в одну папку без вложенности.
- `--naming '{name}_{serial}.{ext}'` задаёт имена. Шаблон задаёт имя файла целиком, поэтому всегда заканчивай его на `.{ext}`: без этого файлы выйдут без расширения. Метки: `{name}` имя исходника, `{serial}` номер по порядку (три цифры), `{serial:4}` четыре цифры, `{date}` дата, `{ext}` расширение. `--start-serial 1` задаёт первый номер.
- `--stop-on-error` останавливает партию на первой ошибке.
- `--error-log файл` пишет, какие файлы не обработались и почему.
- `--quality 1-100` для JPEG и WebP. `--metadata none` убирает из файла XMP и текстовые поля. `--jpeg-format progressive` делает прогрессивный JPEG.

**Windows.** В PowerShell и cmd кавычки внутри JSON в `--params` ломаются. Поэтому на Windows не пиши JSON в командной строке: всегда клади шаги в файл и запускай `batch`. Для одного фото скопируй его в отдельную пустую папку и обработай её.

Некоторые команды работают только через `run`: замеры без сохранения и новый документ с `--new`. Для них на Windows запускай утилиту через `cmd /c` и ставь обратную черту перед каждой кавычкой внутри JSON:

```bat
cmd /c ""C:\путь\photocraft-cli.exe" run кадр.jpg --cmd document.sampleColor --params "{\"x\":60,\"y\":900,\"size\":31}""
```

Это общее правило Windows для кавычек, на этой утилите оно не проверено. Сначала попробуй его на безвредной команде замера. Если JSON не принимается, прочитай текст ошибки и скажи человеку, что именно не прошло.

## 4. Правила, которые нельзя нарушать

1. **Исходники не трогаешь.** Результаты пишешь только в отдельную папку. Ключ `--in-place` не используешь. Папку исходников как папку результата не указываешь.
2. **Сначала один файл.** Любую новую обработку сначала делаешь на одном фото, показываешь результат человеку и ждёшь «да». Партию без этого не запускаешь, даже если задача описана подробно.
3. **Одинаковые настройки на всю партию.** Фото из одной съёмки получают одни и те же шаги, иначе карточки в каталоге выйдут разными.
4. **Товар остаётся как на фото.** Цвет, фактуру, форму и длину вещи не меняешь. Покупатель должен получить то, что видел. Ничего не дорисовываешь.
5. **Не объявляешь готовым непроверенное.** После партии выполняешь проверку из раздела 6. Если что-то не получилось, говоришь прямо, какие файлы и почему.
6. **Чужие файлы не читаешь.** Работаешь только в папках, которые назвал человек.

## 5. Проба на одном файле

1. Выбери типичное фото из партии. Если съёмка неоднородная (разный свет, разный фон), возьми по одному фото из каждой группы.
2. Сделай обработку в отдельную папку `_проба` рядом с папкой результата.
3. Посмотри на результат как на изображение, своими глазами. Если не можешь открыть изображение, скажи об этом и попроси человека посмотреть.
4. Покажи человеку путь к файлу «до» и «после» и коротко перечисли, что сделано.
5. Спроси, что поправить. После правок повтори пробу. Партию запускай после явного «да».

## 6. Проверка после партии

1. Сравни число файлов в папке исходников и в папке результата.
2. Прочитай файл ошибок, если он задан.
3. Проверь размеры трёх случайных результатов через `photocraft-cli info … --compact`.
4. Посмотри глазами первое, последнее и два фото из середины.
5. Отчитайся: сколько обработано, сколько с ошибками, какие фото стоит посмотреть вручную и почему.

## 7. По желанию: PhotoCraft как MCP-сервер

Тот же движок можно подключить к Codex как набор инструментов: тогда ты открываешь документ, выполняешь команды по одной, смотришь слои и получаешь превью без записи файлов. Это удобно для ручной доводки одного сложного фото.

В `~/.codex/config.toml`:

```toml
[mcp_servers.photocraft]
command = "/полный/путь/к/photocraft-cli"
args = ["mcp", "--automation-read-root", "/полный/путь/к/папке/с/фото", "--automation-write-root", "/полный/путь/к/папке/результатов"]
```

Пути только полные. Читать сервер может всё внутри первой папки, писать только во вторую. Давай ему отдельную рабочую папку, а не домашнюю. Основные инструменты: `command_list`, `command_run`, `command_batch`, `doc_inspect`, `render_preview`. Для пакетной работы MCP не нужен, хватает `batch`.

## 8. Что известно заранее

- Читает: JPEG, PNG, WebP, TIFF, PSD, PSB, HEIC, RAW камер (DNG, CR2, CR3, NEF, ARW, RAF и другие). Пишет: JPEG, PNG, WebP, TIFF, PSD, PSB. HEIC и RAW только читает.
- Выделение предмета считается на самом компьютере, без облака. На пёстром фоне, на белой вещи на светлом фоне, на прозрачных тканях и мехе оно ошибается чаще. Такие фото смотри особенно внимательно.
- Большие файлы и RAW обрабатываются заметно дольше. Предупреди человека, если в партии больше 50 фото.
- Если команда отвечает ошибкой, не повторяй её вслепую. Прочитай текст ошибки, сверь параметры через `commands --filter` и только потом пробуй снова.
