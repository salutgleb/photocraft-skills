# Размер и сохранение

Приводит партию фото к одному размеру и пропорции и сохраняет лёгкие файлы с правильным цветом. Только фото, видео этот скилл не трогает.

Перед началом прочитай `../photocraft-base/SKILL.md`. Команды сверь через `photocraft-cli commands --filter`.

## Шаг 1. Что спросить

Нужно знать три вещи. Не спрашивай то, что уже сказано.

1. **Куда пойдут фото.** От этого зависят размер и пропорция.
2. **Что делать, если пропорция фото не совпадает с нужной.** Три способа ниже.
3. **Формат.** По умолчанию JPEG.

Размеры по умолчанию:

| Назначение | Пропорция | Размер |
|---|---|---|
| Карточка товара на маркетплейсе | 3:4 | 1200×1600, минимум 900×1200 |
| Лента Instagram, пост ВК | 4:5 | 1080×1350 |
| Квадрат | 1:1 | 1080×1080 |
| Сторис, рилс, клипы ВК | 9:16 | 1080×1920 |
| Сайт, Telegram, карты | как есть | длинная сторона до 2000 |

Требования площадок меняются. Если фото идут на маркетплейс или в рекламный кабинет, попроси человека сверить размер в справке площадки.

## Шаг 2. Три способа

| Способ | Что получится | Когда брать |
|---|---|---|
| Вписать с полями | Фото целиком, по бокам или сверху и снизу поля цвета фона | Вещь на белом или ровном фоне, ничего нельзя обрезать |
| Обрезать под пропорцию | Кадр заполнен, лишнее по краям срезано | Фото на модели, в интерьере, для ленты и сторис |
| Только уменьшить | Пропорция прежняя, файл легче | Сайт, мессенджеры, архив |

Перед обработкой узнай размеры исходников: `photocraft-cli info фото.jpg --compact`. Если исходник меньше нужного размера, скажи об этом. Увеличение больше чем в полтора раза даёт мыло: предложи меньший размер или другой исходник.

### Вписать с полями

Готовые файлы шагов в `actions/`:

| Файл | Результат |
|---|---|
| `pad-white-3x4-1200x1600.json` | 1200×1600, белые поля |
| `pad-white-4x5-1080x1350.json` | 1080×1350, белые поля |
| `pad-white-1x1-1080.json` | 1080×1080, белые поля |
| `pad-white-9x16-1080x1920.json` | 1080×1920, белые поля |

Внутри два шага: `file.automate.fitImage` вписывает фото в рамку, `image.canvasSize` дополняет холст до точного размера. Для полей другого цвета скопируй файл и замени `"extensionColor": "white"` на свой `"#rrggbb"`. Цвет бери с фона самого фото, иначе будет видна граница.

### Обрезать под пропорцию

Здесь для каждого фото свой прямоугольник, поэтому считаешь его по одному фото.

1. Узнай размер фото: ширина `W`, высота `H`.
2. Узнай, где предмет. Запусти вырезание без сохранения, оно только напечатает ответ:
   ```sh
   photocraft-cli run фото.jpg --cmd layer.removeBackground
   ```
   В ответе `bounds`: `[x, y, w, h]`. Если предмет не найден, считай предметом центр кадра.
3. Посчитай прямоугольник обрезки с пропорцией `r` (ширина к высоте, для 4:5 это 0.8):
   - добавь к рамке предмета запас 8% с каждой стороны;
   - расширь её до пропорции `r` вокруг её центра: если рамка уже, чем нужно, увеличивай ширину, иначе высоту;
   - если прямоугольник вышел за край фото, сдвинь его внутрь;
   - если он больше самого фото, возьми самый большой прямоугольник пропорции `r`, который помещается в фото, с центром как можно ближе к центру предмета. Отметь это фото: предмет будет обрезан плотно или частично.
   - на фото с человеком следи, чтобы прямоугольник не резал голову и ступни. Если не помещается, сдвигай вверх: голова важнее.
4. Обрежь и сразу приведи к размеру одной командой:
   ```sh
   photocraft-cli run фото.jpg \
     --cmd image.crop --params '{"x":120,"y":40,"width":1600,"height":2000,"targetWidth":1080,"targetHeight":1350}' \
     --cmd edit.convertToProfile --params '{"profile":"srgb"}' \
     --out готово/фото.jpg --quality 90 --metadata none
   ```

На Windows вместо `--params` в строке сделай для каждого фото свой маленький файл шагов и запусти `batch` на папке с одним этим фото.

Если человек просит простую обрезку по центру, пропусти пункт 2 и ставь прямоугольник по центру кадра.

### Только уменьшить

Файл `actions/shrink-long-side-2000.json` вписывает фото в 2000×2000 и никогда не увеличивает. Для другого предела скопируй файл и поменяй оба числа.

## Шаг 3. Проба и партия

Сделай пробу на одном вертикальном и одном горизонтальном фото, если в папке есть оба вида. Покажи человеку и жди «да», как описано в базовом скилле.

```sh
photocraft-cli batch \
  --actions actions/pad-white-4x5-1080x1350.json \
  --in ./исходники --out ./готово \
  --format jpg --quality 90 --metadata none \
  --error-log ./готово/_ошибки.txt
```

## Шаг 4. Формат и вес

| Назначение | Формат | Ключи |
|---|---|---|
| Соцсети, маркетплейсы, карты | JPEG | `--format jpg --quality 90` |
| Сайт, где важна скорость | WebP | `--format webp --quality 82` |
| Прозрачный фон | PNG | `--format png` |
| Отдать в печать или дизайнеру | TIFF | `--format tif --tiff-compression lzw` |

- Качество JPEG 90 это разумная середина. Ниже 80 на ткани появляются квадраты, выше 95 файл тяжелеет без пользы.
- Цветовой профиль всегда sRGB: шаг `edit.convertToProfile` уже стоит в готовых файлах. Без него цвет вещи на телефоне покупателя может выглядеть иначе.
- `--metadata none` убирает из файла служебные данные. Ставь для всего, что уходит в интернет.
- Если площадка ограничивает вес файла, проверь размер результата и снижай качество шагами по 5.

## Шаг 5. Имена файлов

По умолчанию имя берётся от исходника. Если нужно своё:

```sh
--naming 'платье-{name}_{serial}.{ext}' --start-serial 1
```

Шаблон задаёт имя файла целиком, поэтому в конце всегда стоит `.{ext}`: без него файлы выйдут без расширения. Метки: `{name}` имя исходника, `{serial}` номер из трёх цифр, `{serial:2}` из двух, `{date}` дата, `{ext}` расширение по формату сохранения. Артикул из имени исходника не выбрасывай: по нему потом ищут фото. В именах для сайта и маркетплейсов лучше латиница, цифры и дефис, без пробелов.

## Шаг 6. Проверка

Проверка из раздела 6 базового скилла и дополнительно:

1. Размер трёх результатов через `info` совпадает с нужным до пикселя.
2. При обрезке: назови фото, где предмет обрезан плотно или частично.
3. При полях: цвет полей не отличается от фона фото.
4. Напиши итоговый вес партии и самый тяжёлый файл.
