# LightCraft: общие правила

LightCraft это бесплатная открытая программа для каталога и проявки фото. В ней есть оценки и флажки для отбора, ползунки света и цвета, пресеты и пакетный экспорт.

Каждое действие в LightCraft это команда с именем вроде `photo.rate` или `develop.set`. Утилита `lightcraft-cli` выполняет те же команды без окна программы. Правки не меняют файлы фото: они хранятся в каталоге LightCraft и попадают в пиксели только при экспорте.

Команды в этих скиллах сверены с исходным кодом LightCraft 0.21.1 и ни разу не запускались. Новые версии выходят почти каждый день. Поэтому сверяй команды с установленной версией (раздел 2) и всегда начинай с пробы на одном кадре (раздел 7).

## 1. Найди lightcraft-cli

| Система | Где лежит |
|---|---|
| Windows, установка для себя | `%LOCALAPPDATA%\Programs\ArtCraft\LightCraft\lightcraft-cli.exe` |
| Windows, установка для всех | `C:\Program Files\ArtCraft\LightCraft\lightcraft-cli.exe`, у 32-битной версии в `C:\Program Files (x86)\ArtCraft\LightCraft\` |
| Windows, переносной архив | рядом с `lightcraft.exe` |
| macOS | отдельный архив `lightcraft-cli-<версия>-macos-universal.zip`, в LightCraft.app утилиты нет |
| Linux, пакеты deb и rpm | `/usr/bin/lightcraft-cli` |
| Linux, архив tar.gz | `bin/lightcraft-cli` в распакованной папке |
| Linux, AppImage | лежит внутри образа, но запуск образа открывает окно. Распакуй образ ключом `--appimage-extract` и вызывай `squashfs-root/usr/bin/lightcraft-cli`. Этот способ не проверен, сверь его |
| Linux, Flatpak | `flatpak run --command=lightcraft-cli ai.storyteller.lightcraft`. Так утилита видит только папку `~/Pictures` и не читает HEIC |

На Windows утилита не добавлена в PATH, вызывай её по полному пути в кавычках. Если программа стоит в другой папке, установщик записал путь в реестр: `reg query "HKCU\Software\LightCraft" /v InstallFolder`. Для установки на всех пиши `HKLM` вместо `HKCU`.

На macOS, если утилиты нет:

1. Скажи человеку, что нужен архив `lightcraft-cli-<версия>-macos-universal.zip` со страницы https://github.com/storytold/lightcraft/releases/latest. Версия архива должна совпадать с версией LightCraft.app. Без согласия человека ничего не скачивай.
2. Распакуй: `ditto -x -k lightcraft-cli-<версия>-macos-universal.zip ~/lightcraft-cli`
3. Проверь подпись Apple: `spctl --assess --type install -vv ~/lightcraft-cli/lightcraft-cli-<версия>-macos-universal/lightcraft-cli`. Должно быть `accepted` и `Notarized Developer ID`. Отметку о проверке Apple macOS ищет через интернет, без сети проверка может не пройти.
4. Дальше вызывай утилиту по полному пути.

Проверка: `lightcraft-cli --version` печатает `lightcraft-cli 0.21.1` или новее. Запомни путь к утилите на время работы. Ниже она везде названа `lightcraft-cli`.

## 2. Сверь команды с установленной версией

Главный источник правды это сама утилита:

```sh
lightcraft-cli commands          # каждая команда и её параметры
lightcraft-cli commands --json   # то же в JSON
lightcraft-cli controls          # каждый ползунок: id, пределы, значение по умолчанию
```

Ключа `--filter` у `commands` нет, ищи по выводу: `lightcraft-cli commands | grep -A1 photo.analyze`, в PowerShell `& $cli commands | Select-String -Context 0,1 'photo.analyze'`. Перед первым запуском в сессии проверь так каждую команду, которую собираешься вызвать. Если параметры в выводе отличаются от скилла, верь выводу и скажи человеку, что изменилось. Справочник лежит в `references/commands.md`.

## 3. Как запускать команды

Всё идёт через `lightcraft-cli run`. Утилита выполняет команды по порядку и на каждую печатает одну строку JSON: `{"command": …, "ok": true, "result": …, "ms": …}`. При ошибке в строке стоит `"ok": false` и текст в `"error"`. На первой ошибке утилита останавливается, с ключом `--keep-going` идёт дальше. Если хоть одна команда не прошла, код выхода не нулевой. Служебные сообщения идут в stderr, в stdout попадают только эти строки.

**Команды в строке.** Слово без `=` начинает новую команду, пары `ключ=значение` дают ей параметры. Значение читается как JSON, если получается (число, `true`, список), иначе как текст:

```sh
lightcraft-cli run --library /полный/путь/_каталог photo.rate rating=3 'ids=[12,13]' photo.flag flag=pick 'ids=[12]'
```

В zsh и bash бери в одинарные кавычки значения со скобками, фигурными скобками и пробелами.

**Файл шагов.** Ключ `--script файл` читает команды из файла, по одной команде на строку:

```text
# строки с решёткой и пустые строки пропускаются
{"command": "library.selectAll", "params": {}}
{"command": "photo.rate", "params": {"rating": 3, "ids": [12, 13]}}
```

Каждая команда целиком стоит на одной строке. `params` это объект, его можно не писать. Команды из командной строки выполняются раньше команд из файла. `--script -` читает шаги из стандартного ввода.

**Windows.** В PowerShell и cmd скобки, запятые и кавычки в параметрах ломаются. Поэтому на Windows каждую команду со списком или объектом пиши в файл шагов. В командной строке оставляй только простые значения: числа, слова, путь в двойных кавычках. В JSON пиши пути с прямой косой чертой `C:/Фото/съёмка` или удваивай обратную `C:\\Фото\\съёмка`.

**Чтение результата.** Сохраняй вывод в файл и потом читай его целиком: `… > _отбор/анализ.jsonl`. В Windows PowerShell 5 знак `>` пишет файл в кодировке UTF-16, там пиши `… | Out-File -Encoding utf8 _отбор/анализ.jsonl`.

**Импорт.** Ключ `--import путь` добавляет файлы до первой команды и выделяет все добавленные. Если хоть один файл не прочитался, утилита не выполняет ни одной команды. Для целой папки надёжнее команда `library.import` в файле шагов и за ней `library.selectAll`, потому что сама `library.import` выделяет только первый добавленный кадр. В файлах шагов пиши только полные пути.

## 4. Каталог съёмки

Без ключа `--library` утилита держит всё в памяти, и оценки, флажки и правки пропадают после команды. Поэтому для съёмки всегда заводи каталог: `--library /полный/путь/_каталог`. Папка создаётся сама при первом запуске. В ней хранятся оценки, флажки, правки, пресеты и миниатюры. Исходники остаются на своём месте.

```text
съёмка/
  исходники/   фото человека, ты их только читаешь
  _каталог/    каталог LightCraft
  _отбор/      анализ, таблица отбора, листы для просмотра
  _проба/      проба на одном кадре
  отбор/       копии выбранных кадров
  готово/      результаты экспорта
```

Если фото лежат прямо в папке, которую назвал человек, создай рабочие папки рядом с ней, в соседней папке с понятным именем. Импортируй только папку исходников, папку с каталогом и результатами никогда.

Каталог открыт только в одной программе за раз. Если окно LightCraft держит этот же каталог, утилита ответит `This library is already open in …`. Попроси человека закрыть окно или открыть в нём другой каталог. Чтобы показать человеку результат в окне, дождись конца своих команд. Потом запусти LightCraft с ключом `--library /полный/путь/_каталог` или открой каталог в меню File, пункт Open Library….

## 5. Ловушки, известные заранее

1. `develop.set` без `ids` меняет только активный кадр. Активный кадр задаёт `active` в `library.select`, иначе это первый из выделенных. `develop.wb`, `develop.wbPick`, `develop.merge` и `crop.straighten` всегда меняют только активный кадр.
2. `lightcraft-cli render` берёт ровно один файл и без `--size` пишет полный размер.
3. `app.export` без размера пишет длинную сторону 3000 пикселей. Полный размер даёт `longEdge` 0.
4. `app.export` с `path` без расширения и без `format` пишет PNG.
5. Неизвестный ключ в `app.export` это ошибка, файл не пишется. Опечатку ищи в тексте ошибки.
6. В фильтре `catalog.query` нет поля `minRating`, хотя подсказка MCP его упоминает. Пиши `"rating": 3, "ratingOp": "atLeast"`. Незнакомое поле фильтр, скорее всего, молча пропускает, поэтому сверяй `total` в ответе.
7. `catalog.query` без `limit` отдаёт 200 кадров.
8. Команда без выделенных кадров отвечает `is not available right now`. Сначала выдели кадры.

## 6. Правила, которые нельзя нарушать

1. **Исходники не трогаешь.** Импорт только в режиме `add`, он стоит по умолчанию. Режим `move` не используешь. Не вызываешь команды, которые меняют или пишут файлы рядом с исходниками: `photo.delete`, `photo.deletePermanently`, `photo.rename`, `photo.moveToFolder`, `photo.duplicate`, `photo.convertToDng`, `photo.editExternal`. Файлы `.xmp` рядом с исходниками (`photo.saveMetadataToFile`, `library.xmpPreferences` с `autoWrite`) пишешь только после «да» человека именно на это. В начале работы вызови `library.xmpPreferences` без параметров: `autoWrite` должен быть `false`.
2. **Сначала один кадр.** Новую обработку сначала делаешь на одном кадре, показываешь результат и ждёшь «да».
3. **Одинаковые настройки на группу.** Кадры одной группы света получают одни и те же настройки, иначе серия выйдет разной.
4. **Вещь остаётся как в жизни.** Цвет, фактуру и форму вещи не меняешь. Покупатель должен получить то, что видел.
5. **Не объявляешь готовым непроверенное.** После партии делаешь проверку из раздела 7. Если что-то не вышло, говоришь прямо, какие файлы и почему.
6. **Чужие файлы не читаешь.** Работаешь только в папках, которые назвал человек.

## 7. Проба и проверка

Проба: выбери типичный кадр из каждой группы, сделай обработку в `_проба/` и посмотри результат своими глазами. Если не можешь открыть изображение, скажи об этом и попроси человека посмотреть. Покажи пути к файлам «до» и «после», коротко перечисли, что сделано, и жди «да».

После партии:

1. Сравни число кадров, которые ты собирался обработать, с числом файлов в папке результата.
2. Найди строки вывода с `"ok": false` и непустые поля `failed` в ответах.
3. Посмотри глазами первый, последний и два кадра из середины.
4. Отчитайся: сколько сделано, сколько с ошибками, какие кадры стоит посмотреть вручную и почему.

## 8. Что известно заранее

- Читает JPEG, PNG, TIFF, WebP, PSD, PSB, JPEG XL, GIF, BMP, HEIC и RAW. Пишет JPEG, PNG, TIFF, PSD, WebP, AVIF, JPEG XL и DNG.
- Полноценно проявляет RAW форматов DNG, CR2, CR3, CRW, NEF, NRW, ARW, RAF, RW2, RWL, PEF и несжатый ORF. Остальные RAW он показывает по встроенному в файл JPEG, у таких кадров в `catalog.query` есть поле `previewOnly`.
- HEIC читают выпуски для Windows, macOS и Linux deb и rpm. Flatpak его не читает. Файлы AVIF программа не открывает.
- Облачных нейросетей и ключей доступа нет. Маски «Небо», «Предмет» и «Фон» строятся простым расчётом по яркости и цвету и бывают грубыми. Маски «Объект» и «Описание» требуют модель SAM 3, а адреса для её загрузки в этой сборке нет. Не обещай их.
- Шумодав AI Denoise (`denoise.toggle`) работает только с RAW обычной байеровской матрицы. Для JPEG и Fujifilm X-Trans его нет.
- Закрытые глаза программа не находит, это проверяешь сам.
- RAW и большие папки обрабатываются заметно дольше. Предупреди человека, если в работе больше 300 файлов или есть RAW.
- Если команда отвечает ошибкой, не повторяй её вслепую. Прочитай текст, сверь параметры через `commands` и только потом пробуй снова.

## 9. По желанию: LightCraft как MCP-сервер

Тот же движок можно подключить к Codex как набор инструментов. Это удобно, чтобы посмотреть кадр с правками без записи файла. Для пакетной работы MCP не нужен, хватает `run`. Настройка в `~/.codex/config.toml`:

```toml
[mcp_servers.lightcraft]
command = "/полный/путь/к/lightcraft-cli"
args = ["mcp", "--headless", "--compact", "--library", "/полный/путь/к/съёмке/_каталог"]
```

`--headless` значит без окна, `--compact` оставляет только основные инструменты: `command_list`, `command_run`, `command_batch`, `doc_inspect`, `render_preview`, `import`, `query_photos`, `select_photos`, `list_controls`, `get_develop`, `set_develop`, `apply_preset`, `crop`, `render_photo`, `export`. Любая команда из `commands` вызывается через `command_run`. Ограничений на папки у сервера нет: он пишет везде, куда может писать пользователь. Пока сервер работает, каталог занят, и `run` с тем же каталогом не откроется.
